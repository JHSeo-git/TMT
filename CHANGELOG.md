# Changelog

## 2026-09-04 - Every palette row looked selected, and the labels are English

- Opening the palette drew every row with the selected background, which made the list read as one solid block. `command.tsx` styles the selected row with `data-selected:bg-muted`, and that compiled here to `.data-selected\:bg-muted[data-selected]` — an attribute-**presence** selector. `cmdk` writes `data-selected="false"` on every row it has not selected, so the attribute is always there and the rule always applied.
- `data-selected:` turns out not to be a Tailwind variant at all. It is a `@custom-variant` declared in `shadcn/tailwind.css`, which shadcn's own `app/globals.css` imports on its third line and this project never did; their build emits `:where([data-selected="true"])` from it, ours fell back to Tailwind's generic `data-*` handling. Not a version difference — `tailwindcss@4.3.3` is the latest and both projects are on it.
- So `app/globals.css` imports the two lines shadcn's own `init` would have added, `tw-animate-css` and `shadcn/tailwind.css`, rather than hand-copying declarations out of them. The stylesheet brings nine `data-*` variants and its utilities, the compiled selector now matches shadcn's output exactly, and one row is filled where ten were. `shadcn` joins `dependencies` for it. The package is only read at build time and nothing of it reaches the browser, so `devDependencies` would describe it more precisely, but a build-time input belongs where an install that prunes dev dependencies cannot remove it — and that is where shadcn's own `init` puts it. `tailwindcss-animate` leaves in exchange, so the dependency count is unchanged.
- Running `init` itself was tried first, in a throwaway copy, and rejected. It merges rather than overwrites, so `@layer markdown` and the fumadocs imports survive, but it also rewrites `--font-sans` to `var(--font-sans)` — a self-reference that breaks the Pretendard variable this project sets in `layout.tsx` — and re-tunes eight theme values plus four `components.json` fields. `shadcn eject` afterwards inlines the stylesheet and drops the dependency, at the price of 619 lines of vendored CSS in `globals.css` and no future updates. The two imports get the same baseline for two lines.
- `no-scrollbar`, on `CommandList`, was the same omission and was doing nothing: the list showed a scrollbar shadcn hides. It reports `scrollbar-width: none` now.
- `@plugin 'tailwindcss-animate'` went with it. `tw-animate-css` is its Tailwind 4 successor and was already a dependency, unimported; with the stylesheet in place it supersedes the plugin outright, verified by removing the plugin and diffing the output — the `animate-in` rule comes out identical and the CSS shrinks 491 bytes. The dialog's enter animation is confirmed running in the browser at `animation-name: enter`, which is worth stating plainly because it was claimed broken earlier on the strength of a regex that could not match `.data-open\:animate-in`. It was never broken.
- The variants also read better than what stock Tailwind produced. `data-open:` now covers Radix's `[data-state="open"]` alongside Base UI's bare `[data-open]`, where before it matched attribute presence only. All of it costs 3,163 bytes raw, 500 gzipped, in the CSS the browser gets.
- Because the stylesheet is the fix, `command.tsx` keeps the registry's own class strings and `shadcn add --overwrite` stays safe. Confirmed by diffing every utility token in the installed component against the published `base-vega` payload: identical but for `lucide-react`, which is the CLI substituting a real icon for the registry's `IconPlaceholder`. Nothing about the install is stale — the `cn-command-item` classes visible in `registry/bases/base/ui/command.tsx` belong to a CSS-layer variant defined in `registry/styles/style-vega.css`, and the endpoint serves the pre-expanded component instead.
- Rows no longer show the item's date. It was the only thing in the palette payload beyond a number and a title, and dropping it took the per-page cost from 9KB gzipped to 7KB — a quarter of it was dates nobody searches by.
- The palette's text is English now, and its groups read `Pages` and `Text` rather than `아이템` and `본문`, with `Recent` before anything is typed. Note that `CONTEXT.md` makes **item** the word for the unit and `Pages` is a new one alongside it; the glossary is worth a look if this wording is meant to stick.

## 2026-09-04 - The palette caps what it renders, and drops a debounce it never needed

- Typing in the palette stuttered. The route answers with every match it has — 1,129 body results for `에이전트` — and all of them were rendered, so the list held 1,185 rows, 6,811 nodes, 2,008 highlight elements, and stood 56,852px tall inside a 288px window. `cmdk` re-runs its filter across every mounted row on each keystroke and React reconciles the survivors, so one keypress with that list mounted measured **185.7ms**. Against the same harness and the same query it now measures 7 to 22ms, median 15 — inside a frame or two, with 38 rows and 210 nodes.
- Each group therefore caps its rows: 30 titles, 8 body results. Body rows carry the highlight elements and are the expensive ones; a title is a single line. The cap is applied **after** matching, not before — capping the archive first would have hidden anything past the newest few rows, and it very nearly did. `트레이드` returns `설계 트레이드 오프`, the 293rd and last item in the archive, which is the check that catches that mistake.
- Filtering moved out of `cmdk` entirely. Titles are matched here by substring and body results were already decided by the server, so `cmdk` is handed rows that are all keepers and scores nothing per keystroke. That also removed the marker-prefix trick the previous release needed to stop `cmdk` re-filtering server results.
- `useDocsSearch` debounces on its own through `delayMs`, which the previous release did not use — it wrapped the hook in a second 300ms timer instead, so the round trip waited 400ms and the component carried a duplicate copy of the query. The timer and the extra state are gone; `delayMs` is 200 and the hook's own `search` value drives the title tier immediately.
- The palette's own markup now follows the registry component instead of overriding it. The `max-h-[60vh]` override is gone, so the list is `max-h-72` as shadcn ships it; body rows are one line rather than two, so every row is 32px like the rest; and the arbitrary `text-foreground/55` and `text-foreground/50` are replaced by `text-muted-foreground` and the treatment `CommandShortcut` gives trailing metadata. Checked against the live component on shadcn's own docs: item 32px at 6px/8px padding, list 288px, heading 12px, container 4px padding and 14px radius all match. Item radius is 10px rather than 6px because the component deliberately rounds rows more inside a dialog.
- The `CommandEmpty` override was deleting itself — `py-6 text-center text-sm` is already that component's default.

## 2026-09-04 - Search over the archive, opened with ⌘K

- Two tiers behind one palette. The 293 item titles are already on the client — the layout hands them over — so typing filters them with no round trip, which is what finding a known item wants. In parallel `/api/search` returns section-level matches whose links carry the heading anchor, so a half-remembered sentence lands on the heading it sits under rather than at the top of the item. `⌘K`, `Ctrl+K`, and `/` open it, all three ignored while focus sits in a field; before anything is typed it shows the ten newest items rather than all 293, and closing always clears the query so it never reopens on the last search.
- No search service and no new search dependency. `fumadocs-core` was already here for MDX, and it exports `createSearchAPI` directly: its `indexes` option takes a function returning the entries, which is the same seam `createFromSource` is built on, so nothing about the search needs the items to be MDX files on disk. `@orama/orama` came along with fumadocs already.
- Korean needed no configuration, which was checked rather than assumed. The tokenizer defaults to `multilingual` in `fumadocs-core@16.15.4` and its `language` and `localeMap` options are marked deprecated as no longer needed. `샌드박스` does not match the title `샌드박싱` in the title tier, and no client-side filter would; the body tier catches it along with prefixes and typos.
- The index has to run on the server. Serialized it is 43MB, 10.4MB gzipped, for 293 items, which settles any idea of shipping it to the browser. A cold instance answers its first query in about five seconds — three GitHub requests at 3.2s, then `structure()` over every body and Orama's index at about 1.7s — and warm queries then run between 2 and 27ms depending on the term. It is held in module scope, so concurrent requests during that build share it rather than each starting another.
- The route carries no caching on purpose. `unstable_cache` has a per-entry size limit that 2.4MB of bodies would run into, and Next 16's `"use cache"` needs the top-level `cacheComponents` flag, which changes caching and prerendering for the whole app — too much for one route. The title tier covers the wait, so the cost shows up only as body results arriving late on a cold instance. If that starts to bite, the first move is computing `structure()` at build time.
- `structure()` needs cleaning up after, for reasons visible in its output rather than guessed at: a GFM table is shredded into one chunk per cell, so a three-column table contributes chunks reading `방식`, `오버헤드`, `격리`, and a blockquote keeps its `>` marker in the text. Single-token chunks are dropped and a leading `>` is stripped, verified as zero single-token text results across several queries. Fenced code blocks produce no chunk at all, so an API name that appears only inside one is not findable.
- The palette is shadcn's `command`, and it cost less than expected — worth recording because the opposite was assumed while designing it. `cmdk` depends on four Radix packages and every one was already in the lockfile: `fumadocs-ui`, which renders the item bodies, declares ten Radix dependencies directly with `react-dialog` among them. So `package.json` gained one entry, the lockfile gained one package, and the Radix count stayed at 34. Radix has never actually left this project. Under the `base-vega` style the component composes `@base-ui/react/dialog` and `input-group`, so the rendered tree stays on Base UI, and the `IconPlaceholder` import and `cn-*` classes the repository's own registry sources carry are absent from the published version, so nothing needed stripping.
- `cmdk` filters items by their value, which is right for titles and wrong for body results, since the server already ranked those and a chunk matching `격리 구조` need not contain that string contiguously. A custom filter waves them through: measured, `격리 구조` keeps 498 body results where `cmdk`'s own filter would have left none. shadcn replaces `cmdk`'s scorer with substring matching in the same way, so the title tier is ordered newest-first rather than by relevance — which is what an archive wants, and worth knowing before reaching for `cmdk` on the strength of its scoring. Its scorer was checked against Korean first: across 42 title-query pairs it agreed with a plain substring test every time.
- Highlighting arrives as `<mark>` markup inside `content`, so it is parsed into elements rather than injected as HTML, and the chunk around it is dimmed to 55% so the matched run reads as the highlight without needing a colour of its own. Verified in the browser: 155 `mark` elements at weight 600 against dimmed surrounding text, and no escaped markup anywhere in the list.
- The palette adds 9KB gzipped to every page — 35KB raw — measured against the deployed build of the same item. The alternative, if that ever needs cutting, is a generated static JSON the palette fetches on first open, which trades an instant first tier for zero page weight.
- Orama Cloud was considered and is not used. As of 2026-09-04 the library is free and the managed product is a flat monthly price with a required four-hour onboarding; the former hobby tier is gone. At 293 items there is nothing for it to solve, and `fumadocs-core` ships both halves of an Orama Cloud adapter, so switching later is a change to the route and the hook rather than to the design. `docs/design/site-search.md` holds the numbers this was decided on.

## 2026-09-03 - The item's headings become a rail in the left gutter

- Replaced the item page's table of contents. The 286px "On this Page" panel in the right gutter and the `Index` back-link in the left gutter are both gone, and in their place a rail of ticks sits pinned to the middle of the left gutter — one tick per heading, a step shorter for every nesting level, with the tick for the heading in view filled in. Clicking the rail opens the headings as a 240px list. The shape follows [Substack's article TOC](https://addyo.substack.com/p/agentic-skill-decay) closely: 12px ticks 1.5px tall, 2px shorter per level, 12px apart, `left: 8px`, vertically centred.
- The reason for the swap is that the old layout spent both gutters on navigation an item page barely needs. The right panel listed every heading permanently at the cost of a third of the page's width, and the `Index` link duplicated the `TMT` link already sitting under the title. The rail costs 28px and reads as a position indicator first, a menu second.
- The rail opens on click and then stays put. Picking a heading navigates without dismissing the panel, so several jumps in a row cost one click each, and only `Escape` or a click outside closes it. Hover does nothing but light the rail's own background. That is Substack's contract, checked against the page rather than assumed: a real pointer hover leaves its trigger at `data-state="closed"`, and its menu is still `open` after a heading has been picked.
- Rebuilt `components/toc.tsx` as one component, `TocRail`, and it needs no interaction state. It renders fumadocs' `AnchorProvider` itself and reads the active heading through `useActiveAnchor`, so the `TOCContext` that used to carry the heading list from the page down to a separate renderer is gone, and so is the page's `TOCProvider` wrapper — the page now passes the compiled `toc` straight in as `<TocRail toc={toc} />`. Base UI's Popover owns the click toggle, `Escape`, outside-click dismissal, and the focus handoff, and because picking a heading deliberately leaves the panel up there is nothing left for the component to control: the `<Popover>` is uncontrolled, and the file holds no state, no refs, no timers, and no mouse handlers. It is 77 lines whose only logic is the depth-to-indent mapping.
- Positioned the panel with `positionMethod="fixed"`, which needed a prop added to `components/ui/popover.tsx`. Base UI positions a popup absolutely by default, and the rail it anchors to is fixed to the viewport, so holding the panel still across a scroll meant rewriting its transform every frame — measured directly: over 2718px of scrolling the positioner's `translateY` moved 2718px in lockstep with `scrollY` purely to stay in place. Any frame the main thread missed against a compositor-driven scroll showed up as the panel sliding up and down. Positioning it the way the rail is positioned leaves nothing to recompute; the same measurement now reports a `translateY` delta of 0 across the same scroll, with the panel's on-screen rect identical to before. shadcn's `PopoverContent` forwards only `align`, `alignOffset`, `side`, and `sideOffset` to the positioner, so `positionMethod` joined that list — passed through rather than defaulted, leaving every other popover on Base UI's `absolute`.
- Deleted `components/clerk.tsx` along with `TOCScrollArea` and `TocThumb`. Those drew the vertical progress line down the right-hand panel by measuring anchor offsets and masking an inline SVG — about 140 lines of layout measurement that the rail has no use for, since a tick's own width and colour carry everything the line used to say. `lib/merge-refs.ts` existed only for them and went too.
- Nesting depth is measured from the shallowest heading present rather than assumed to start at `h2`. Item bodies are written by hand and start at whichever level the author chose, so a body whose headings begin at `h3` still gets a full-length tick for its top level.
- The rail is hidden below 1024px (`max-lg:hidden`). Substack's cut is 816px, but the article here is `max-w-[60ch]`, and around 900px the left gutter narrows to where the ticks start touching the text. Nothing was lost on small screens: the old right-hand panel was hidden below 1280px.
- One known limit: each tick occupies 13.5px, so an item with more than roughly 60 headings would run past the viewport. The longest item in the archive has 7. Substack does not clamp its rail either, so neither does this.
- Verified against a production build — 105 pages generated, no type or lint errors — and in the browser at 1440px with real pointer and keyboard input: ticks measure 12px for `h2` and 10px for `h3`, a real hover does not open the panel but still lights the rail, a click does open it, two headings can be picked in a row from one opening with the active tick and active row both following, scrolling neither dismisses the panel nor is locked by it, an outside click and `Escape` each close it with focus returning to the rail, panel rows indent 8px and 20px by level, and items with no headings (#1, #302) render no rail at all.

## 2026-09-03 - The list moves to `/`

Every internal link in the app already pointed at `/` as home (`app/i/[issueNo]/error.tsx` and both `not-found.tsx` files), so those links now resolve directly instead of through a redirect hop.
- Moved `app/p/not-found.tsx` to `app/not-found.tsx`, which promotes it from a `/p`-segment boundary to the app's global 404. It now covers `/i` and any other unmatched path, where Next's default page used to show.
- Fixed a missing issue answering 500 instead of 404. `getIssueByNo` re-throws GitHub's 404, so the `notFound()` guard sitting below it was never reached and the error boundary answered instead — which also meant `app/i/[issueNo]/not-found.tsx` had never once rendered. `/i/abc`, `/i/0`, and `/i/-3` answered 500 too, from a `throw new Error("Invalid issue number")` guarding the parse. Both are bad URLs rather than server faults, so the route now answers 404 for either.
- The fix lives entirely in the route: `loadIssue` catches the fetch, calls `notFound()` when the caught error carries status 404, and rethrows everything else to the error boundary. `lib/github.ts` is untouched, so a network fault, a bad token, and a rate limit all keep travelling exactly as before.
- Collapsed the parse-validate-fetch sequence that `generateMetadata` and `IssuePage` each carried into one `loadIssue` helper. That duplication is why the bug survived: both copies held a working `notFound()` guard underneath a throw that shadowed it, so fixing one would have left the other.
- Known noise from leaving the data layer alone: `getIssueByNo` still logs `failed to fetch(fetchIssue)` with a stack trace before rethrowing, so a normal 404 writes two error lines per request — one from `generateMetadata`, one from the render. Silencing it would mean branching on the status inside `lib/github.ts`, which this shape deliberately avoids.
- Verified against a running build: `/` returns 200 with all 100 list links and `/i/321` and `/i/1` return 200, while `/p`, `/i`, `/i/99999`, `/i/abc`, `/i/0`, and `/i/-3` all return 404 rendering the app's own not-found page.
- One consequence to be aware of: the removed `/` → `/p` redirect was `permanent: true`, which browsers cache as a 308 with no expiry. A returning visitor may still be sent from `/` to `/p` by their own cache and land on a 404 until they clear it. Nothing in the app can undo a cached 308 — the options are to live with it or to serve `/p` again temporarily.

## 2026-09-03 - The `published` gate and secondthought's work queue

- Renamed the publish gate from `learn` to `published`. GitHub's label rename was used rather than creating a new label and re-applying it, so the label stayed attached to all 293 items. `learn` ("Today I learned") had nothing to do with whether something was published, and `published` sits in exact opposition to the existing `draft` (ADR 0002).
- Split labels into three namespaces by owner: unprefixed labels (`published`, `draft`, `secret`) belong to a human, `topic/` and `secondthought/` belong to secondthought. One rule — **a label containing a `/` belongs to the machine, one without belongs to a human** — defines the agent's entire write scope, and no misjudgment on its part can reach the publish gate or `secret`.
- Created the eight `topic/` labels plus `secondthought/needs-topic` and `secondthought/skipped`. A queue label needs an exit, which is why `skipped` exists: leaving an undecidable item (no body, or a personal record outside the topic axis) in the queue would keep the queue from ever emptying.
- Brought the app onto the new label scheme. `lib/labels.ts` holds the gate constant and the `topic/` display-name map, and `lib/github.ts` replaced the hardcoded `"learn"` and its `// TODO` comment with a constant reference. `app/p/page.tsx` now selects only `topic/` labels, draws them under their display names, and hides state labels. Alongside that, the eight lines of label normalization duplicated across two functions collapsed into `toLabelNodes`, which filters nameless labels at the data layer so the render side never handles `string | undefined`.
- Found and fixed a separate omission bug while verifying. Item #109 "Augmented Coding: Beyond the Vibes" demonstrably carried the gate label yet was missing from label-filtered queries, so it was not appearing in the site's list. Its timeline shows the label removed and re-applied on 2025-08-27, and GitHub's filter index appears to have gone out of sync from that point. The omission predates the rename and is unrelated to it; toggling the label once more forced a re-index and resolved it.
- Built the topic-labeling work as the `.agents/skills/applying-topic-labels/` skill and linked it into `.claude/skills/` by relative symlink. The skill is deliberately not named after the agent: the skill is the work and `secondthought` is what will do the work automatically, and calling both by one name would blur the distinction once the GitHub Action lands.
